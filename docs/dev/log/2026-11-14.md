# 2026-11-14

## MCP over HTTP from the open app (`experimental`)

- Agents no longer start `buildcraft3d --mcp`. While the app is open with the assistant and "External agents (MCP)" on, it serves MCP over Streamable HTTP at `http://127.0.0.1:47833/mcp/<token>` (`src/mcp/http.rs`); the server stops with the switch or the window. Decision in [ADR-0004](../decisions/ADR-0004-ai-agent-can-drive-the-tools.md#update-2026-11-14).
- The port is `ai.mcp_port` (default 47833); the token is a UUID kept in the config folder (`mcp-token`, mode 0600). A bind error shows under the switch like the listener's.
- Registrations use the URL: `claude mcp add -s user --transport http`, `codex mcp add --url`, `opencode mcp add --global --url`, `gemini mcp add -s user -t http`; Antigravity shows an `mcp_config.json` entry with `serverUrl`. "Show setup" shows the URL and the command.
- Detection: an agent counts as registered when its `mcp list` shows the current URL (checked for `claude` and `codex`); one that lists `buildcraft3d` otherwise is shown as outdated, and turning it on removes the old entry first.
- `src/mcp.rs`: stdio and HTTP share `reply`/`handle`; the client's own JSON-RPC responses get no answer; the accept loop and the private-file writer are shared by both ports. `--mcp` and its token-line port stay for custom commands.
- Checked live with a temporary config on port 47900: initialize 200, notification 202, tools/list 24 tools, get_scene and insert_shape 200, GET and DELETE 405, wrong token 404, foreign Host 403, foreign Origin 403, chunked 400, bad JSON 400; `claude mcp list` (in a throwaway home) reports it Connected; `--mcp` still reaches the window; the port closes when the app exits.
