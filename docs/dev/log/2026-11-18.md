# 2026-11-18

## MCP fixes from a blind test of every tool (`experimental`)

A tester that only saw the MCP server (descriptions, schemas, instructions) called every tool. Fixes:

- **Hollow crashed the app** on a plain 30 mm cube with a 2 mm wall (also from the UI's Hollow tool). Root cause: manifold-rust's `level_set` sizes its first hash table for a sparse surface (10·√cells) and, when it fills, resizes from the position of the last vertex that snapped to the surface; with none it panics ("table full before any vert", `sdf.rs:748`). A grid point snaps only when it lies within a quarter cell of the surface. A box's inner walls are big flat faces parallel to the grid, all at the same fraction of a cell; when that fraction is between 1/4 and 3/4 no point snaps, the crossings of the first face fill the table and it panics. 15 of 51 cube/wall combinations (12–60 mm, walls 1–3 mm) crashed. `solid::level_set` now meshes on whole cells from a corner shifted by 0, ½ or ¼ cell, trying the next shift when the library panics; between them every flat face lies near grid points in one. Regression test: cubes of 30/27/45/57 mm hollow to a closed solid with a cavity between the wall and the wall + 2 mm.
- **Panics no longer close the app**: `buildcraft3d::no_panic` turns a panic into an error. `modify_selected` (Hollow, Smooth, Extrude down… from the UI and the agent) runs each object's operation through it, so a failure is a notice and the scene stays as it was; every agent call runs through it too and returns a tool error. The default panic hook still prints the message (and a backtrace with `RUST_BACKTRACE`) to stderr.
- **Split** with a plane that misses a selected object deleted it (keep top below the object) or replaced it with a copy. `cut::misses` checks the plane against each object; `Scene::cut_pieces` now fails with "z 200 is above the top of the object (29.97 mm); nothing to cut" (or the bottom, or "the plane misses … which lies wholly below it" for a slanted plane), changing nothing. The UI's Split shows the same notice. Pieces keep the object's material.
- **measure** with no arguments and nothing selected returns the usual "nothing is selected" error (`mcp::nothing_selected`, shared with the other selection tools).
- **paint_area**: coverage is the largest bend between neighbouring faces the paint crosses (coverage × 180°), so on a smooth sphere every edge bends a few degrees and a small coverage floods it. Same as the UI's Coverage slider, which is unchanged. New `radius` (mm): only triangles whose centre is within it of `point` (Euclidean, the paint still spreads only through connected triangles; `Mesh::face_region_within`). The description now says this. The texture brush's coverage has the same behaviour and no radius yet.
- **get_scene** lists per object `material` (none/simple/realistic/translucent, `Material::name`), and `painted`, `textured`, `stickers`. `set_material`'s description is exact: any type but none sets the colour and clears painted areas; textures and stickers stay; none only removes the material.
- **Unknown or mistyped arguments** are rejected for every tool in one place, `mcp::check_args`, from the tool's own `inputSchema` (also nested objects such as `custom`, and `oneOf`). Run in `serve_agent`, so MCP clients and the in-app chat get it. Errors list the tool's arguments ("unknown argument units: transform takes back, bottom, front, …") or the type with the unit from the description ("size must be [x, y, z] in mm, three numbers; for cm multiply by 10").
- **edit** gains `group` and `ungroup` (the app's Group/Ungroup: one object without merging shapes; one object per separate solid). Ungroup checks `Mesh::solids`, so a hollowed object (outer shell plus cavity) is not "several solids".
- Wording: split/open/import say ids change; open clears the undo history and selects what it opened; insert_shape/import/load_image land at the centre of the floor and may overlap; load_image's 0.6 mm base (depth 3 = 3.6 mm tall, not for edge); spherical emboss is raised lettering, a sticker is a flat picture; extrude_outline no longer mentions keychains; smooth keeps about its size; measure's gap is 0 where boxes touch or overlap; screenshot's window picture includes open dialogs; GIF/BMP/WebP/TIFF say "isn't supported; convert to PNG" (`picture::unsupported`), and import of one gets the load_image hint; `file_name` without content and emboss_text with several objects selected have their own errors.

Noticed, not changed: the UI's Ungroup button is enabled for a hollowed object (`can_ungroup` counts mesh components, which include the cavity) and does nothing.

- `mcp::check_args` also rejects a value outside a parameter's `enum` and lists the
  choices, before the tool runs (an unknown `edit` operation used to report "nothing is
  selected" first).

## Measure: radius and snapping (`experimental`)

- **Radius**: the Measure tool has a mode list: Distance, Radius of a surface (a click on a curved face fits a cylinder or a sphere to the face's triangles, up to 30° between neighbours; flat or non-round faces say "Not a round surface") and Radius from 3 points (the circle through them, live with the cursor as the last point). The tool bar shows Radius and Diameter in the scene units; the viewport draws the fitted circle (three for a sphere) and a radius line in the same faint-wide plus thin style as the distance line. Model in `src/measure.rs`.
- **Snap**: the existing Snap switch (on by default) now snaps picked points to the vertex, edge middle, edge or face centre of the flat face under the cursor within 14 px (converted to mm at that depth), else keeps the point on the face plane; the floor is a plane too. A yellow marker with its name shows what was caught (square vertex, triangle midpoint, diamond edge, circle face centre, cross plane). The second point of a distance is lined up with the first: perpendicular distance when both lie on parallel faces (or the floor), exact along an axis within 3°. Holding Alt turns the Snap setting around while measuring. The original's Measure only has a Snap toggle (H54); the marker shapes and Alt are ours.
- **MCP / assistant**: `measure` gains `diameter_of` (object id: sphere, cylinder, cone/torus widest circle), `circle` (3 points), and `snap`, `snap_tolerance` (mm, default 1) and `align` for from/to/circle; the assistant uses the same tool list. `--measure` for screenshots takes `[distance|surface|circle:]x,y,z;x,y,z;~x,y,z@vertex` (the `@kind` only sets the marker; surface fits the face nearest the first point).

## Measure: one tool for diameters, "Section at height" (`experimental`)

Decision: every diameter, radius, centre and wall thickness is measured with the section (`src/section.rs`, Measure mode "Section at height", MCP `measure {section:{...}}`). Two other approaches were built and compared on generated shapes and on the user's 19 flower pots, then dropped: circular edges (feature edges, open boundaries and creases over 40°, chained and circle-fitted) and a "soft" variant of them (crease angle 6° for rounded rims). Edges find nothing on a cone's wall, a torus or a rounded rim, need a threshold per model, and leave open which of a dozen close rings is the rim; the section gave the exact outer and inner diameter, centre and wall everywhere. Both were removed with their caches, MCP arguments (`edge_loop`, `edge_loops`, `soft`, `edge_angle`), the `--measure edge:` preset and benches. Kept: Distance, Radius of a surface, Radius from 3 points, snapping and the centre markers.

- **Mode "Section at height"**: a click cuts the clicked object horizontally at the clicked point's height (synchronously, 6 to 23 ms), draws every contour (yellow, the contour nearest to the click green, with the diameter line and the centre cross) and the bar shows Radius, Diameter and Center of that contour plus every round contour (Outer / Inner diameters) and the Wall. `--measure section:x,y,z`.
- **Clicking a rim, a base, a hole**: the plane then lies in a flat face (the top or bottom of a cylinder, a cone's base, the rim of a hollow tube) and cuts no material. `section` detects a triangle lying in the plane (within half of `SHIFT`, 2e-4 of the object's largest size: 0.02 mm on a 100 mm pot) and slices that hair inside the solid on both sides, keeping the side with a contour nearest to the click (the larger cut area when no point is given); the contours are projected back onto the clicked plane, so centres are exact. `Section::shift` and the MCP `shifted_mm` and `note` say it. A hollow cylinder clicked on its rim gives outer and inner diameter and the wall; the nearest contour to the click is the one highlighted and answered as `nearest`. A ledge (a disc under a post) is resolved by the click too: the post's base picks the post, the disc's top edge the disc.
- **MCP**: `section` takes `near [x,y,z]` alone (horizontal plane at that point's Z, `nearest` filled), `z`, or `point` + `normal` for any plane (`near` then only picks `nearest`). The tool and schema descriptions (also the in-app assistant's, same list) say `section` is the way to get diameters, centres and wall thickness, rims, bases and holes included. A smooth rounded rim has no flat top: slice a few mm under it.
- **Models used by the comparison**: `primitives::revolve(profile, n)` builds solids of revolution; `tests/measure_models.rs` checks cylinders, cones (radius at each height), a torus, hollow pots with a flat and rounded rims against their exact geometry, and has an ignored table for the real pots in `/run/media/nico/KODAK/3D/Macetas/Robert/`: `cargo test --offline --release -j 4 --test measure_models -- --ignored --nocapture`.
- **Real pots** (first slice with a round outer contour, going down 1 mm steps from the top): outer 79.1 to 79.8 mm on the medios and 108.3 to 111.0 on the grandes, inner 72.8 to 73.1 (100.1 to 101.9), wall 2.3 to 4.7 mm, 1.5 to 15.5 mm under the top (the crown of a rounded rim is too thin to be a circle; why some pots need up to 15 mm was not looked into). Others are different pots: Mascotas 75.9, Serio 76.2 and 105.9, Lector acostado 81.2, Madre e hijo 102.0. Latency 6 to 12 ms per cut on 0.4 to 0.7M triangles, 22 ms on Mascotas (1.28M); welding the mesh dominates and there is no cache.
- Not verified by hand: the hover and click in the real window (the section is cut on click, no hover highlight), the screenshot of the bar and overlay (`--screenshot` hangs here), the MCP over the running Flatpak.

## MCP argument limits and blind-test fixes (`experimental`)

Three agents with no context tried every tool of the running app. `emboss_text {"text": "X", "size": 100000}` hung the app for minutes and killed it: the pattern is sampled on a grid of at most 2 mm, so the work grows with its area, and nothing bounded size, width, text length or the other numbers.

- **Limits**: `src/mcp/args.rs` holds every range as a named `Limit` (`limits::COORD`, `OBJECT_SIZE`, `EMBOSS_SIZE`, ...), the helpers that read arguments (`number`, `integer`, `vec3`, `text`, `ids`, `choice`...) and the parsers of the heavy tools (`emboss`, `load_image`, `extrude_outline`, `split`, `transform`, `custom`, `wall`, `passes`, `simplify_remove`), moved out of `src/app/` so a test can drive them without the UI. Errors name the argument and the range ("size must be a number between 1 and 200 mm"); the tool descriptions print the same constants. The emboss sizes are the ones the bar already had (`emboss::SIZES`, `DEPTHS`, `STRETCHES`), plus `emboss::MAX_AREA` (100000 mm² for the pattern's box, checked in `layout`, so the UI and Load image's edge mode get it too) and a text of at most 60 characters (a union of glyphs: 100 wide letters took 8 s, 16 with bevel).
- **Measured** (cube, optimized test profile): emboss size 1000 took 6.5 s and size 100000 never finished (killed after 110 s); size 200 with width 4000 and depth 50 took 21 s; 100 letters with bevel 16 s; Load image `edge` at size 500 took 53 s. Now they are refused in microseconds; the slowest accepted case (60 W with bevel, spherical) takes 2.5 s.
- **What bounds the UI thread**: a tool runs on the UI thread (`serve_agent`) and the caller waits with no timeout, so only the ranges bound it; `tests/mcp_limits.rs` runs every heavy tool at the edges of its ranges and with extreme values (0, negative, 1e-9, 1e9, 1e300, very long strings) and fails over 20 s or on a panic. Not bounded: files (capped at 256 MB, inline 25 MB), a mesh the user already loaded, and the boolean library's own time on a big scene; a scene holds at most 1000 objects when a tool adds one.
- **measure snap**: `snap_tolerance` 0 now turns snapping and `align` off; a facet of a curved surface (neighbouring faces bend 45 degrees or less, `FaceInfo::curved`) has no normal to line up along, so `align` no longer projects onto facets; `snapped` lists `{kind, object, curved_face}` per point.
- **Other**: `changes` (created, removed and modified ids) in every answer that changes the scene; the notices a tool call raises are English whatever the UI language (`i18n::in_english`); `save` explains an unwritable or missing folder; `hollow` refuses a wall of half the thinnest side or more at once (it hit the level-set panic path, which was caught); `list_fonts` takes `limit`; the section messages read "encloses 84% of its fitted circle ... needs at least 85%" and "a closed contour of 4 vertices is a polygon, not round (a cube gives a square)".
- Descriptions: the current selection (insert, split, emboss, import and load_image change it), which tools keep an object's id and which replace it, `extrude_outline keep_model false` deleting the original, smooth's triangle counts, custom shapes' triangle counts, emboss's colour and depth, hollow's closed top, print leaving the job in the slicer, sandbox paths.

## Second blind test of the MCP tools (`experimental`)

A tester with no context stress-tested every tool again. Verified in code first; what was true was fixed with a test:

- **save**: `args::save_path` takes only an absolute path naming a file with an extension (a folder such as `/tmp`, a relative path or a name without extension is an error; it no longer writes `/tmp.3mf`); the answer carries `saved_to` and `bytes`. Like the UI's Save as it names the scene after the file (the default title; a title set with `model_info` stays), which the description now says. `io::save` tells a folder that does not exist (a Flatpak app has a private `/tmp`) from one that exists but is not writable (`/proc`, `/root`).
- **Files**: `io::load` drops objects without triangles and fails with "The file has no triangles" when none is left; a file with its own units (3MF, glTF, SVG) over `io::MAX_SIZE_MM` (10000, now also `limits::OBJECT_SIZE`'s maximum) is refused with the limit named; STL/OBJ/PLY are checked at their units in `import` and `open` (`PendingImport::check_size`, which suggests `units`). `load_image` was not affected: an SVG picture is drawn at 1024 px and sized by `size`, and no method gives an empty mesh (tested).
- **Arguments**: `check_args` now looks inside lists of objects (`print_setup` `filaments[i]`; `custom` and `section` were already checked); `print_setup` checks every filament choice before making any; null still means "not given" in every tool (said once in the rules); colours go through `args::color`/`io::parse_hex` and accept the `#` or not (documented); the "for cm multiply by 10" hint only goes with numbers out of a length's range; `screenshot` `size` clamps every whole number and refuses decimals; `args::normal` gives `section` and `split` the same range and wording; `section` without `id` says so.
- **Empty objects**: `mcp::require_geometry` is the one guard (measure's selection, ids, diameter_of, section, and every tool that acts on the selection except `edit delete`).
- **JSON-RPC**: a batch or a bare value gets -32600 (HTTP 400) instead of 202 with no body.
- **split**: z on the bottom or top says "z must be strictly between the bottom and the top"; a finite plane that leaves (almost) nothing to cut is an error (`cut::unchanged`) instead of replacing the object. **hollow**: a cavity under one voxel says "the wall is too thick for this size" (a 10 mm cube takes 4.5 mm, not 4.99). **transform** with nothing to do answers with a `note`. The edge-mode area error of Load image no longer mentions text.
- **Not a bug**: `get_scene` `size` is the world (axis-aligned) bounding box (description fixed); `smooth` without edges does grow a cube (10 mm becomes 10.8 mm after 3 passes, volume 80%), so the description and the code comment now say so; `diameter_of: null` is "not given" by the rule above.
- Descriptions: hollow's open-top advice and wall accuracy, diameter_of for cones and spheres, section on a cone's flat face, `ids` and the "B 25 mm right of A" example, which ids emboss_text and extrude_outline keep, `edit` subtract/undo, split limits. The per-argument description limit went from 700 to 900 characters.

## Flicker on entering a tool (`experimental`)

Since 4808262 a new mesh was drawn first with the provisional smooth shading and swapped for the real one when the worker finished, so entering Simplify on a cube showed it rounded for a frame or more, then flat. Confirmed by reading `Renderer::sync_mesh` (every new `Arc<Mesh>` took that path, and tool previews replace the object's mesh) and by `tests/mesh_cache.rs`.

- `mesh_cache::MeshCache` (in the library, generic over the GPU copy) decides the copy per object (`DrawItem::owner`): up to 10k triangles (`SYNC_SHADING_TRIANGLES`, ~2 ms, from `shading_cost_by_size`) the real shading is computed inline; above it the object keeps its previous copy until the worker answers; the provisional shading (now flat per-triangle normals) is only for a first load with nothing to show.
- Copies not drawn are kept as spares (4, 1.5M triangles), so cancelling a tool, undo and redo do not shade again.
- Tests: first upload equals the final shading for a cube and a sphere; shading requests per tool entry (Simplify, Hollow, Smooth previews, leave, undo, redo) equal the number of distinct meshes; the held copy is shown, never the provisional one; stale worker results are dropped (`scene.rs` tests). Bench `new_mesh_ui_cost`: see the Performance section of `architecture.md`.
- Not checked by eye: `--screenshot` hangs on this machine.

## Measure: hover cursor, label and snap flicker (`experimental`)

- Removed the snap indicator with its text label and the arrow at the hover point; the system pointer is no longer hidden while placing points. The faint line to the cursor and the live distance stay; placed points keep their arrows. `--measure` no longer takes `@kind`.
- Snap bug, reproduced by `src/measure/sweep.rs` (a synthetic cursor swept in 1 px steps across a cube from four views, first point on the corner, each of the three faces as its normal): `align` moved the second point to the line through the first point whatever the cursor distance. On the face opposite the first point's (Perpendicular) the whole face snapped to the corner across; on the first point's own face the offset along the normal is rounding noise (about 1e-5 mm), which toggled the alignment on and off from pixel to pixel and made the point jump to the first point. `align` now takes a reach (the 14 px in mm at that depth, as the other snaps); the MCP tool passes infinity, so its results do not change. The floor distance now aligns only when the cursor is near the line down from the first point.
- Cost: one pick plus one `measure_spot` per frame with the pointer over the view (a click repeats it once). `FaceInfo::new` (rebuilt only when the triangle under the cursor changes) 0.3 ms on a 3.6k-triangle pot; `snap_point` with the face cached about 1 us.
